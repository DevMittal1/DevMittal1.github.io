04 / KG-RAG
Knowledge Graph RAG — Legal Document Intelligence
Structured, relationship-aware retrieval over 50K+ legal documents for multi-hop reasoning
Neo4jLlamaIndexspaCy NERGraph TraversalOpenAI EmbeddingsFastAPICypher
Problem
A law firm's 50K+ documents — contracts, case law, filings — had no unified retrieval. Standard vector RAG failed on cross-document questions like "which precedents contradict Clause 7 in this contract?" Flat chunking destroyed relational context.
My Role
Designed the KG schema (entities: Party, Clause, Case, Precedent, Date; relations: cites, contradicts, amends, involves). Built the NER pipeline, graph ingestion, hybrid retrieval combining vector similarity with Cypher graph traversal, and the query-to-graph translation layer.
Architecture
Doc Ingest → spaCy NER → Neo4j KG
User Query → Vector + Cypher → Subgraph → LLM Answer
Hybrid retrieval: vector search seeds candidate nodes; Cypher traversal expands 2–3 hops to surface related entities. Subgraph serialized as structured context for the LLM.
Results
83%Retrieval accuracy
+22ppvs vanilla RAG
2.1sP90 latency
Multi-hop accuracy improved most. Lesson: graph traversal depth must be capped — 4+ hops degraded precision severely.
